## Disclosure (under one minute)

This is a synthetic reporting prototype. The Upright-style portal and browser
replay are simulated, not a live vendor integration. All fixture data is synthetic.
The existing fixture contribution is reused unchanged. React, Express, PostgreSQL,
Drizzle, Orval, Zod and the Replit scaffold are borrowed open-source/platform
components; implementation includes AI-assisted code. Arithmetic is deterministic,
not calculated by AI. No sponsor credentials, real customer data, approved
Business Central posting, production security approval or measured time savings
are claimed. Live retrieval, approved AI and finance integration require review.

## Current workflow mappings

Upright evidence: Reports → Paid orders → date/channel/payment controls →
Generate → optional email modal → past-report status/link → download.
Known uncertainty: live columns, exact waiting rules and permitted automation.
The screenshot's order-level/Pacific form is adapted to synthetic
paid-order-item/Eastern semantics and must say so visibly.

CashMonkey: Reports → Orders Report → date range → report link/download;
lower-priority acquisition, distinct fixture parser. Other source classes:
portal exports (ShopGoodwill/eBay/Amazon/books), carrier files/email exports
(shipping/FedEx), workbook/batch exports (jewelry). All are synthetic here;
none is a live connector.

Daily Excel-style output is a proposed compatibility layout:
`reporting date | source | store/Unknown | gross items | item refunds |
net items | definition version | coverage | batch reference`.
Customer/listing/backlog tables stay separate from financial columns.
Actual daily-sheet formulas are unconfirmed. Month-end allocation is a separate
source → enrichment/allocation workbook → journal/invoice → BC workflow, not
a sum of daily dashboard cards. Preserve current finance workflow until parity
and human accounting review exist.
