not a universal recorder/browser or the financial calculator. A claimed successful
model action is not completed acquisition; the browser must download verified bytes.

### Conditional central sequence

No reviewed discovery/recipe UI labels were found. The acquisition owner must
attach the real launch/review/replay click path and artifacts to the readiness
record before recording. The following are **required actions**, not invented
buttons claimed to exist:

1. Display the exact execution mode and approval for this synthetic environment.
   No live URL, login flow, paid access or alternative-model fallback is introduced.
2. Set A: Upright / paid_order_items, `2026-08-01`–`2026-08-07`, Eastern, all
   channels, paid items, CSV. Show observed unique controls and approved actions.
   Code supplies date/filter values; model choices cannot invent selectors, URLs,
   scripts, financial facts or free-form credentials.
3. Start supervised discovery. Narrate allowed observation → decision → browser
   action. Include abstain, low-confidence/budget/cancellation as stop states,
   not invisible retries. Show actual provider record only if it really ran.
4. Show terminal actual download + filename/size/hash/period/header validation.
   Discovery ending or model “done” is not enough. No verified bytes means stop.
5. Open the actual proposed recipe artifact and version. R checks its supported
   source/report, parameter binding, uniqueness, expected page states, completion
   assertions and failure/manual instructions. Show actual explicit approval
   record (reviewer role, timestamp, recipe version/hash, policy version).
6. Select that approved recipe version, change only start/end dates to B, execute
   model-free replay. Show real download and exact hash, plus run-scoped call log
   confirming zero. No discovery is automatically promoted or repaired.
7. On drift, stop; propose a new version for review, keep existing approval
   separate. Do not let an AI “heal” report selection without approval.
8. Restore A for intake/metric/evidence/Sazzle. Preserve A/B separately.

**Current executable baseline alternative after environment clearance:** foundation
Start/End dates → **Generate report → Download CSV → Import CSV file**. For the

scenario, **Start run**, verified-run **Download (not publish)** and intake actions;

**Fallback if current preview fails:** open saved A/B browser-check cases and
actual CSVs with labels. The verified download evidence remains meaningful,
but there is no live integrated workflow or recorded macro proof.

## Sazzle: three prepared questions

**Current mode: CONCEPT answer cards.** No supplied Sazzle recording or working
connection was found. Do not present these answers as actual chatbot outputs.
If the owner supplies a recording, label it RECORDING and verify its scope and
citations; if a working build is supplied, complete the gates below first.

Shared question context: A, Upright / paid_order_items, USD, Eastern, all stores,
same immutable publication/definition as the dashboard and evidence CSV.
Concept cards intentionally contain no fabricated publication ID or clickable
source citation to an unqueried result.

| Order / prompt | Expected answer boundary | Evidence to show / disqualifying answer |
|---|---|---|
| 1. “For synthetic Upright paid-order items, August 1–7, 2026, all stores in Eastern time, what are net item sales?” | “$7,591.21 under the demo net-item-sales definition: $8,041.79 gross less $450.58 item refunds. Excludes shipping, tax and fees.” Retrieve deterministic backend result; do not recompute with a model | Same A query/publication/version/coverage as dashboard; backend fact and citations. Wrong dates/source, whole-company revenue or a newly model-calculated result fails |
| 2. “Which report supports that answer, and how can I verify it?” | Explain source/report/A, actual acquired filename/hash/run, intake batch, accepted source rows, definition and pinned publication; distinguish export checksum from acquired-file checksum | Citations open to the same authorized evidence, exact-file provenance and selected rows. No invented IDs, inaccessible generic citations or claims of live Upright |
| 3. “What were Goodwill's net margin, revenue per labor hour and sell-through for that week?” | “Unavailable. Approved costs/allocations, period-aligned labor hours and a complete approved cohort/inventory denominator are missing. Net item sales is not margin.” | Unsupported policy, no invented zeros/percentages, no fallback to source payout or in-store 50–55% target |

The 45-second script uses concise answers; longer evidence exploration belongs
in Q&A. Missing buyer data makes customer coverage partial, not revenue divided
by an invented customer count.

## Concise Q&A

| Question | Answer |
|---|---|
| “Did AI calculate those dollars?” | No. Exact decimal inputs become integer cents in deterministic data code; independent Python Decimal controls provide a separate expected ledger. Sazzle may explain retrieved facts, not establish financial truth |
| “Did you really download a report?” | Existing lane evidence includes actual browser-downloaded CSV bytes from the simulated portal. Browser tests use archive/repository doubles; a live integrated raw archive requires separate delivery proof |
| “Is this real Jev?” | Not established in this checkout. Actual authorized provider calls, scripted tests and model-free deterministic replay are labeled separately. No discovery/speed/cost claims from scripted tests |
| “What happens when the page changes?” | Baseline replay stops on missing/ambiguous controls. Repair must be reviewed and versioned; no autonomous change to a financial workflow |
| “Why not add the nine sources?” | Different grains and potential overlap. Shipping is expense; Books/Amazon timing differs. No approved system-of-record/key mapping permits a company-wide revenue/customer sum |
| “Are 141 rows 141 customers?” | No, they are accepted paid-item rows. Customers require platform/day buyer keys and completeness; missing buyer IDs remain disclosed. Daily distinct counts are not a unique period total |
| “Why not show margin, YTD or budget?” | Required costs/labor/denominators/comparable periods/budgets are absent or unapproved. Unsupported is unavailable, never zero |
| “Is CSV ready for Business Central?” | No. Spreadsheet-friendly CSV and evidence export are not approved journal/invoice mappings, validated BC import or posting. Finance must validate workbook parity and sandbox outputs |
| “Does it use tools Goodwill already pays for?” | The prototype is not a Microsoft-approved deployment. Excel/Power BI-compatible outputs and Copilot policy are pilot design constraints to validate with Goodwill; no replacement purchase assumed |
| “How much time or money does this save?” | We have interview estimates and synthetic file correctness/control evidence, not measured staff savings or ROI. Baseline real runs and human repair effort before estimating |
| “Can they start Monday?” | No production-readiness claim. Need live authorization, policy/finance definitions, support owner, independent acceptance and a protected parallel pilot |
| “What did you build versus borrow?” | Original workflow/data/control/application implementation is separated from supplied synthetic fixtures, screenshot/process guidance, open-source/platform scaffold and AI-assisted coding. Only reviewed implemented work is claimed |
