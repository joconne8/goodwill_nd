## Rehearsal checklist

### A. Before rehearsal

- [ ] Confirm named P/D/R/E, recording/submission/liaison owners above.
- [ ] Choose exact accepted build and approved **synthetic-only** data/environment.
      No live partner/customer data or vendor sessions.
- [ ] Read delivery acceptance + runbook; attach existing evidence in the slots.
      Do not run a separate full test suite or change implementation to make a demo.
- [ ] Confirm app healthy. The failed preview from this audit must be resolved
      by the delivery owner; static script rehearsal can proceed meanwhile.
- [ ] Choose primary A and second B; know all three expected amount fields,
      rows, size/hash and metric definition. Never carry full-August labels into A.
- [ ] Confirm A acquired-file → batch → publication → metric/evidence/export
      identity ledger. Sazzle uses exactly the same A result if enabled.
- [ ] Choose current mode for S2/S3: authorized Jev, scripted provider,
      approved zero-call recipe, deterministic baseline, manual or test evidence.
      Ensure label is visible and speaker uses matching wording.
- [ ] Find actual recipe version/approval if included. No approval artifact means
      no “we approved/discovered a macro” claim.
- [ ] Complete Sazzle gates or select explicit concept/recording fallback.
- [ ] Select one delivery-approved safe failure: simulated DOM drift OR edited
      copy rejection. Preserve immutable original; do not alter supplied fixtures.
- [ ] Keep known-good A/B files and original controls offline with checksums.
      Keep approved recorded backup only if one actually exists.
- [ ] Close personal tabs; use a clean demo profile; hide account identifiers,
      password managers, notifications, credentials, cookies and signed URLs.
- [ ] Validate safe screens contain no real PII; synthetic buyer IDs only as needed.

### B. Clean and replay run states

- [ ] Delivery owner supplies clean-state method in runbook. For retained
      foundation, fresh approved empty demo database is documented in
      [README](../../../README.md); never delete/reset a shared or existing DB.
- [ ] Announce if using pre-existing publications or previously approved recipes;
      clean-start is not staged by hiding history.
- [ ] Run A acquisition; show verified download, then separate intake.
- [ ] Run B by parameter change with same recipe if approved; verify exact bytes;
      no overlapping or cumulative total. Restore A before metrics.
- [ ] Confirm A validation/counts/reconciliation/source rows and publication.
- [ ] Replay A exact file; point to duplicate/reference and unchanged total/identity
      as applicable to accepted implementation. No revenue addition.
- [ ] Trigger approved safe failure, show exception/next action and same last-good.
- [ ] Dashboard filters/exports restore A/upright/all stores and same pinned revision.
- [ ] Listings/backlog are unavailable under Upright; any supplemental platform/
      snapshot is explicitly separate, with declared coverage and one timestamp.
- [ ] Sazzle questions are either actual verified outputs, labeled supplied
      recording, or visibly concept. Unsupported question remains unavailable.
